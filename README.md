# Токеноскоп

Настольная утилита на Electron: разбирает транскрипты Claude Code (`~/.claude/projects/**/*.jsonl`, в том числе сессии Claude Desktop) и показывает, куда уходят токены — суммарно, по проектам, сессиям, потокам и агентам, по содержимому контекста. Внутри можно прочитать сам транскрипт любого потока, журнал и скрипт прогона воркфлоу и сохранить транскрипт в Markdown или HTML.

Ещё он держит в синхроне Code-сессии между аккаунтами Claude Desktop: всё, что начато под одним аккаунтом, открывается и под другим, а переключение сводится к «Log out → Log in» (см. [ниже](#синхронизация-аккаунтов-claude-desktop)).

Транскрипты только читает: ничего не отправляет и не меняет в них. Пишет Токеноскоп только в сайдбары Claude Desktop — и только когда синхронизирует аккаунты.

## Скачать

Последний релиз (ссылки всегда ведут на свежую сборку):

| Система | Файл |
|---|---|
| Windows 10/11, x64 | [Tokenoscope-win-x64.zip](https://github.com/ianepanda/tokenoscope/releases/latest/download/Tokenoscope-win-x64.zip) |
| macOS, Apple Silicon (M1 и новее) | [Tokenoscope-mac-arm64.dmg](https://github.com/ianepanda/tokenoscope/releases/latest/download/Tokenoscope-mac-arm64.dmg) |
| macOS, Intel | [Tokenoscope-mac-x64.dmg](https://github.com/ianepanda/tokenoscope/releases/latest/download/Tokenoscope-mac-x64.dmg) |
| Linux, x64 | [Tokenoscope-linux-x64.tar.gz](https://github.com/ianepanda/tokenoscope/releases/latest/download/Tokenoscope-linux-x64.tar.gz) |

Сборки делает GitHub Actions ([build.yml](.github/workflows/build.yml)): на каждый пуш в `main` — артефакты прогона, на тег `v*` — релиз с этими четырьмя файлами.

### Запуск на macOS

1. Какой файл брать: меню Apple → «Об этом Mac». «Чип Apple M…» — `mac-arm64`, «Процессор Intel» — `mac-x64`.
2. Открыть `.dmg` и перетащить «Токеноскоп» в «Программы» (Applications).
3. Первый запуск. Приложение не подписано сертификатом Apple, поэтому macOS его не откроет и скажет, что не может проверить разработчика. Нажать «Готово», затем «Системные настройки → Конфиденциальность и безопасность», внизу у строки про «Токеноскоп» — «Всё равно открыть» и подтвердить паролем. Дальше запускается как обычно.

   То же одной командой в Терминале — снять карантин с приложения:

   ```
   xattr -dr com.apple.quarantine /Applications/Токеноскоп.app
   ```

Транскрипты читаются из `~/.claude/projects`; другие папки добавляются в настройках.

### Запуск на Windows

Распаковать zip куда удобно и запустить `Tokenoscope.exe` из папки `Токеноскоп-win32-x64`. Если SmartScreen пишет «Windows защитил ваш компьютер» — «Подробнее → Выполнить в любом случае»: exe тоже не подписан.

### Запуск на Linux

Распаковать архив и запустить бинарник:

```
tar -xzf Tokenoscope-linux-x64.tar.gz
cd Токеноскоп-linux-x64
./Tokenoscope
```

Нужен графический десктоп с GTK: на обычной Ubuntu или Fedora всё уже есть, на голой системе доставить `libgtk-3-0`, `libnss3` и `libasound2`. Если Electron ругается, что `chrome-sandbox` настроен неправильно (так бывает, когда ядро запрещает непривилегированные user namespace), выдать хелперу песочницы права в папке приложения:

```
sudo chown root:root chrome-sandbox && sudo chmod 4755 chrome-sandbox
```

Можно и запускать с `--no-sandbox`, но тогда рендерер работает без песочницы.

## Сборка

Сборка из исходников — под текущую ОС (или `node scripts/build.mjs --platform=… --arch=…`; под macOS — только на macOS):

```
npm install
npm run build            # Windows: dist\Токеноскоп-win32-x64\Tokenoscope.exe, macOS: dist/Токеноскоп-darwin-arm64/Токеноскоп.app, Linux: dist/Токеноскоп-linux-x64/Tokenoscope
npm run build:install    # Windows: то же + ярлыки «Токеноскоп» на рабочем столе и в меню «Пуск»
```

Запуск без сборки, для разработки: `npm start`. Иконка рисуется скриптом `npm run icon` (без внешних библиотек) в `build\icon.png`, `build\icon.ico` и `build\icon.icns`. Если сборка упала с `EPERM` — это антивирус держит свежий `electron.exe`; скрипт сам повторяет попытку.

Первый запуск разбирает всё за несколько секунд (1,2 ГБ транскриптов ≈ 2,5 с в пуле worker-потоков), дальше — из кэша в папке данных приложения (`%APPDATA%\Токеноскоп`, на macOS — `~/Library/Application Support/Токеноскоп`, на Linux — `~/.config/Токеноскоп`). Пока приложение открыто, оно следит за папкой транскриптов и обновляет сводку, не чаще раза в 20 секунд. Ctrl+R (на macOS — Cmd+R) — обновить вручную, F12 — инструменты разработчика.

## Что внутри

| Экран | Что показывает |
|---|---|
| Обзор | стоимость в ценах API, запросы, токены, попадание в кэш; столбцы по дням с разбивкой по компонентам, потокам, моделям или проектам; самые дорогие проекты и сессии; «Что можно улучшить» — эвристики по текущему срезу |
| Проекты | проект = рабочая папка сессии, worktree'ы сведены к репозиторию |
| Сессии | все сессии среза; карточка сессии — график контекста основного потока с компактами, расход по часам, потоки (основной, субагенты, прогоны воркфлоу до агентов), состав контекста, самые дорогие куски |
| Воркфлоу и агенты | прогоны: агенты, шаги, стартовый и пиковый контекст, effort; типы агентов; самые дорогие агенты |
| Что в контексте | на что ушла входная стоимость: файлы, стартовый промпт, вывод модели, вставки, shell, MCP…; категории и самые дорогие куски |
| Инструменты и модели | вызовы и объём результатов по инструментам, effort по потокам, модели, скиллы и MCP-серверы |
| Время и лимиты | неделя лимита (день и час сброса — в настройках), 5-часовые окна, тепловая карта день × час |
| Просмотр | транскрипт потока с usage и стоимостью каждого шага, вызовами и результатами инструментов, поиском; журнал и скрипт прогона. Из «самых дорогих кусков» открывается ровно то место, где кусок появился. «Сохранить» — транскрипт в Markdown или HTML, как его показывает Claude (см. ниже) |
| Аккаунты Claude | сколько сессий в сайдбаре каждого аккаунта и чего где не хватает; синхронизация, мастер переключения аккаунта, автоматика, журнал с отменой (см. ниже) |
| Настройки | папки с транскриптами, цены, неделя лимита, тема, полный пересбор кэша |

Фильтры сверху (период, проекты, модели, потоки) действуют на все экраны, кроме карточки сессии, просмотра и аккаунтов — там всегда всё.

## Синхронизация аккаунтов Claude Desktop

У каждого аккаунта в Claude Desktop свой сайдбар Code-сессий — папка с файлами `local_*.json` в `…\Packages\Claude_*\LocalCache\Roaming\Claude\claude-code-sessions\<аккаунт>\<организация>`, по файлу на сессию. Транскрипты при этом общие (`~/.claude/projects`), поэтому «перенести сессию» — значит создать в другом аккаунте запись, которая открывает тот же транскрипт. Экран «Аккаунты Claude» показывает, чего где не хватает, и делает это сам. Логика выросла из [claude-code-sessions](https://github.com/craigstoller/claude-code-sessions) (converge и retitle) и скрипта ccs-switch, но работает без них.

**Куда пишется.** Приложение держит сайдбар текущего аккаунта в памяти и перезаписывает его, а сайдбары других аккаунтов не трогает: под каким аккаунтом оно открыто, видно по его же журналу `%LOCALAPPDATA%\Claude\Logs\main.log`. Поэтому Токеноскоп пишет в «свободные» аккаунты, не закрывая Claude, а в текущий — когда переключишься или закроешь Claude. Если по журналу не понять, под кем Claude (идёт вход, приложение ещё запускается), не пишет никуда. Если во время записи в Claude сменили аккаунт или запустили его, запись останавливается.

**Что переезжает.** Каждая сессия, у которой есть транскрипт и запись хотя бы в одном сайдбаре. Запись собирается из транскрипта (папка, модель, effort, время, число реплик) по тому же шаблону, что у claude-code-sessions, а не копируется с чужой: разрешения, MCP-серверы и вкладки Chrome другого аккаунта не переносятся. Время последней активности тоже выравнивается — сессия, с которой работал под другим аккаунтом, поднимается в сайдбаре наверх.

**Что не переезжает.** Удалённое в аккаунте (`deleted_<id>`) туда не возвращается. Старая ветка после rewind не едет туда, где уже есть её продолжение. Без ответа модели, без рабочей папки или с транскриптом, который пишется прямо сейчас, запись собрать не из чего — такие сессии видны во вкладке «Не переносится» и переедут, когда это изменится.

**Названия.** Заданное руками расходится по всем аккаунтам. Разные сессии с одинаковым названием различаются датой: старая ветка после rewind — «… (до ДД.ММ ЧЧ:ММ)», просто тёзка — «… (ДД.ММ ЧЧ:ММ)», самая свежая остаётся как есть.

**Как пользоваться.**

- «Синхронизировать» — записать всё, что можно записать сейчас.
- «Переключиться на …» — мастер: переносит всё в другой аккаунт, подсказывает сделать в Claude Settings → Log out и войти, по журналу Claude видит вход и переносит новое обратно. Claude закрывать не нужно, сессии не обрываются.
- «Закрыть Claude и синхронизировать всё» — как ccs-switch: дожидается, пока закроешь Claude, синхронизирует все аккаунты, включая текущий, и запускает его снова.
- «Синхронизировать автоматически» — новые сессии и названия расходятся по свободным аккаунтам сами, через несколько секунд после появления; после входа под другим аккаунтом — сразу. Одни только времена активности автоматом обновляются не чаще раза в полчаса. Фоновые синхронизации видны системным уведомлением.
- «Работать в фоне» и «Запускать вместе с системой» — Токеноскоп сидит в трее и синхронизирует, даже когда окно закрыто.

**Если что-то не так.** Каждая синхронизация сначала записывается в журнал (`%APPDATA%\Токеноскоп\account-sync\ops`), последнюю можно отменить кнопкой в «Журнале»: добавленные записи удаляются (если их с тех пор не переименовали и это не последняя запись сессии), у обновлённых возвращаются прежние значения. Если Токеноскоп закрыли посреди записи, при следующей синхронизации он сверит по байтам, что успело лечь. Свежий файл, который держит антивирус, переписывается с повторами. С claude-code-sessions одновременно не пишет: держит его блокировку.

Запись проверена только в Windows; на macOS и Linux экран показывает, чего где не хватает, но ничего не меняет.

## Сохранение транскрипта

Кнопка «Сохранить ▾» в просмотре транскрипта (любой поток, в том числе агент) и на карточке сессии (основной поток) сохраняет переписку в `.md` или `.html` в том виде, в каком её показывает Claude Desktop в обычном режиме (Transcript view → Normal):

- сообщения пользователя — как простой текст, без разметки: так их показывает Claude; в том числе набранные, пока Claude работал, и слэш-команды;
- ответы Claude — целиком, Markdown;
- вызовы инструментов подряд, без текста между ними, — одной свёрнутой строкой-сводкой по правилам Desktop: у одиночной команды и агента — их описание («Show working tree status»), у группы — счётчики по категориям, самые частые первыми, не больше трёх частей («Выполнено 3 команды, прочитано 2 файла, поиск по файлам»);
- компакты, прерывания, ошибки API (в рамке), завершение фоновых задач, главы Desktop.

Размышления, сами команды, результаты инструментов, системные вставки и тексты скиллов в файл не попадают: в нём только то, что видно на экране. HTML — одна самодостаточная страница (светлая и тёмная тема, картинки из сообщений встроены); ссылки в ответах кликабельны только для http(s). Диалог сохранения открывается в папке прошлого экспорта.

## Как считается

- **Дедуп.** Один ответ API пишется в транскрипт несколькими строками с одинаковым usage — считается один раз по `message.id`. Копии запросов в ветке после rewind достаются исходной сессии.
- **Стоимость** — в эквиваленте API по таблице цен из настроек (по умолчанию — цены на 27.09.2026; модель сопоставляется с самым длинным совпавшим префиксом id). Запись в кэш на 5 минут — 1,25 × цены входа, на час — 2 ×, быстрый режим — множитель. Для подписки это мера того, насколько быстро расходуется лимит, а не счёт: реальные правила лимитов Anthropic не публикует.
- **Состав контекста.** На каждом шаге агент отправляет весь свой контекст. Он раскладывается на стартовый контекст сегмента (системный промпт, инструменты, CLAUDE.md) и всё, что пришло потом: результаты инструментов (по инструменту, для shell — по программе), системные вставки, сообщения, собственный вывод модели. Размер кусков оценивается по символам и на каждом шаге калибруется по реальному размеру контекста из usage, поэтому доли в сумме дают ровно входные токены шага. Входная стоимость шага делится по этим долям; генерация ответа — отдельная строка.
- **Самые дорогие куски** — токены куска × число шагов, которые он проехал в контексте после появления; ≈$ — по цене чтения кэша.

Цифры сверены со скриптами замеров из статьи «Экономия токенов в воркфлоу Claude» (27.09.2026): неделя 20–26.09 — 18 824 запроса, 4 690 181 888 токенов чтения кэша, 9 611 456 вывода, до токена.

Ограничения оценки: схемы инструментов, подгруженные через ToolSearch, в транскрипте не видны (их размер уходит в общую калибровку); изображения оцениваются как ~1600 токенов.

## Для разработки

- `node scripts/check.js 2026-09-19T21:00:00 2026-09-26T21:00:00` — разбор без Electron и итоги за окно (время — UTC).
- `node scripts/export.js <id сессии | файл.jsonl> [--format=html] [--out=путь]` — то же сохранение транскрипта без Electron; по умолчанию в `out/`.
- `node scripts/dev-server.js` — тот же интерфейс в браузере на http://localhost:5178, с веб-заглушкой API (сохранение — скачиванием).
- `npx electron . --capture=out.png --view=context --size=1440x1000 [--theme=light] [--session=<id> --open=transcript]` — снимок экрана без показа окна (своя папка данных, не мешает запущенному приложению).
- `node scripts/sync-check.js` — проверка синхронизации аккаунтов на песочнице: копия настоящих сайдбаров (транскрипты только читаются), переключения, закрытие Claude, отмена, удалённые сессии, остановка записи при смене аккаунта.
- `node scripts/sync-sandbox.js build` и `state --running --live=<id> | --signed-out | --closed` — песочница вручную: копия сайдбаров, свой main.log и выдуманный список процессов. С ней `node scripts/dev-server.js 5179 --sandbox` (или `TOKENOSCOPE_SYNC_SANDBOX=<папка> npm start`) показывает экран «Аккаунты» и пишет в копию. Без песочницы dev-сервер в сайдбары не пишет.

Устройство: `lib/parser.js` — разбор одного транскрипта (usage, состав контекста по шагам, тяжёлые куски, статистика инструментов); `lib/scanner.js` — поиск файлов, кэш, пул worker-потоков; `lib/dataset.js` — сессии, проекты, треды, глобальный дедуп, колоночные массивы; `lib/transcript.js` — чтение для просмотра; `lib/export.js` — сохранение в Markdown и HTML (Markdown ответов в HTML рендерит `marked`, он лежит в `lib/vendor`). Синхронизация аккаунтов: `lib/desktop.js` — где сайдбары, запущен ли Claude и под кем (по main.log); `lib/facts.js` — что новой записи нужно из транскрипта; `lib/accsync.js` — план, запись, журнал, отмена; `lib/sync-service.js` — наблюдение за журналом и сайдбарами, автоматика, мастер переключения. Интерфейс — Preact + htm без сборщика (`renderer/`), графики нарисованы на SVG.
